# 실제 모델 A/B 파일럿

이 실험은 harnessay가 발견한 큰 셸 출력 문제를 바탕으로 작성한 짧은 지침이,
이 저장소의 읽기 전용 유지보수 작업에서 도움이 되는지 확인합니다.
제품 전체의 비용 절감이나 자동 최적화 효과를 증명하는 벤치마크는 아닙니다.

## 고정한 조건

- 작업 5개: 날짜 경계 확인, 사용량 입력 검증, 포크 처리 확인,
  실제 기록의 익명화된 집계 비교, 오프라인 검사 3종 실행.
- baseline: 기존 README·AGENTS·스킬과 일반 과제 지시.
- guided: baseline과 같은 조건에 제한된 탐색·출력 지침을 추가.
- 지침에는 정답이나 작업별 해결법이 없습니다. 사람이 기록 분석 결과를 보고 작성했습니다.
- 과제·정답·지침·순서는 첫 실행 전 manifest에 고정합니다.
- 각 과제를 두 조건에서 2회 반복합니다. 총 20회, 10쌍입니다.
- 각 쌍은 순차 실행하며, baseline 먼저 5쌍·guided 먼저 5쌍으로 무작위 배치합니다.
- 각 호출은 독립된 새 세션입니다. 같은 소스 스냅샷·모델·추론 설정·읽기 전용 환경을 사용합니다.
- 원본 대화와 프로젝트 경로는 모델에 제공하지 않습니다. 비교 입력은 익명화된 기존 집계입니다.

## 측정

정확한 JSON 값과 명령 실행 기록을 검사합니다. 오프라인 검증 과제는 실제
명령과 종료코드를 확인해야 통과입니다. 실패·시간 초과도 결과에 보존합니다.
입력 토큰, 그중 캐시된 입력, 출력 토큰, 경과시간, 셸 호출 수와 셸 출력 바이트를
별도로 기록합니다. 캐시 토큰을 입력에 다시 더하지 않습니다.

완료 시간에는 CLI 시작과 도구 실행도 포함됩니다. 무인 실험이므로 실제 사용자
개입은 0회이며, 개입 감소 효과를 주장할 수 없습니다. 캐시는 완전히 통제하지
못합니다. 독립된 작업 수는 20개가 아니라 5개입니다.

## 재실행

실제 호출은 계정 사용량을 소비합니다. 모델을 명시해야 합니다.

```bash
python3 experiments/test_benchmark.py
python3 experiments/benchmark.py --out benchmark-runs/new-pilot --model <model> --effort high
```

기존 경로로 실행하면 저장된 manifest와 동일한 모델·설정으로 미완료 일정만
이어서 실행합니다. `--limit 1`은 기록 형식을 확인하기 위한 첫 1회 실행입니다.
같은 경로에서 제한 없이 다시 실행하면 나머지를 진행하며 첫 실행을 중복하지 않습니다.
기본 시간 제한은 호출당 180초입니다.

`benchmark-runs/`는 Git에서 제외합니다. manifest, 답변, 원시 CLI 이벤트,
오류 출력, 결과 JSONL을 남겨 수치를 추적할 수 있게 합니다. 외부 배포는 하지 않습니다.

스냅샷 준비에는 이 저장소의 `report-before.json`과 `report-after.json`이 필요합니다.
공유되지 않는 로컬 입력이므로 다른 환경에서는 먼저 두 집계를 생성해야 합니다.

## 이번 실행에서 수정한 실험 조건

읽기 전용 환경은 기존 검사의 임시 파일 생성까지 막았습니다. 원래 20회 기록을
보존하고, 검사 과제만 임시 스냅샷에 쓰기가 가능한 환경에서 양쪽 2회씩 별도로 실행했습니다.

```bash
python3 experiments/benchmark.py --out benchmark-runs/new-offline-correction --model <model> --effort high --sandbox workspace-write --only offline-checks
```

첫 보정 호출에서는 출력 없이 정상 종료하는 검사를 채점기가 실패로 판정했습니다.
채점기는 실제 Python 실행과 종료코드를 확인하도록 수정했고 회귀 검사도 추가했습니다.
원시 결과는 수정하지 않고 재채점 결과를 `reviewed-results.jsonl`에 별도로 보관합니다.
최종 측정과 해석은 [실험 보고서](../docs/BENCHMARK.ko.md)에 기록합니다.
