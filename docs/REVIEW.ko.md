# harnessay 폴더 분석 및 개선 요약

검토일: 2026-09-28

## 후속 적용 현황

우선순위 1~3(측정 정확도, 전후 비교, 원문 추적)을 추가 구현했습니다.

- Codex 첫 소유자 메타데이터 유지, 부모가 확인된 포크 구간 제외,
  관련 세션의 도구·응답 ID 중복 제거를 기간 필터보다 먼저 수행합니다.
- 손상된 JSON·인코딩·중첩 필드·미지원 형식·읽기 실패를 진단으로 집계합니다.
- `--until`로 종료일을 지정하고 `--json-out`으로 스냅샷을 저장합니다.
  `--compare`는 같은 스키마·도구의 이전 JSON과 총량·세션당 지표를 비교합니다.
- 큰 출력·재읽기·스킬 후보에 원문 파일·물리적 줄 번호·시각을 연결합니다.
- 기간 경계는 UTC [시작일, 종료일)이며 날짜 없는 기록은 기간 분석에서 제외합니다.
- ID와 확인된 경계가 없는 상속 이력은 여전히 제한이 있습니다.
  원문 링크는 파일을 열며, 편집기의 특정 줄로 자동 이동하는 기능은 아닙니다.

아래 표는 최초 검토 당시의 전체 로드맵입니다. 위 항목과 겹치는 내용은 구현되었으며,
파일·테스트 결과 기반 평가, exec 내부 분석, 프로젝트 필터, 익명화·스킬 초안은 후속 범위입니다.


## 1. 이 프로젝트가 하는 일

Claude Code와 Codex의 로컬 대화 기록을 분석하는 Python CLI·스킬입니다.
도구별 출력 크기, 프로젝트별 사용량, 압축 횟수, 같은 내용의 파일 재읽기,
반복되는 도구 호출을 정적 HTML로 보여줍니다. 별도 실행기는 CLI에 과제를
주고 답변을 검사합니다. 서버·DB·외부 Python 패키지는 필요하지 않습니다.

핵심 가치는 단순 사용량 표시보다 **여러 프로젝트에서 반복되는 작업을 찾아
스킬이나 지침으로 정리할 근거를 제공하는 것**입니다. 현재의 “낭비”는 제한된
규칙에 따른 추정이며, 큰 출력이 반드시 불필요했다는 뜻은 아닙니다.

| 위치 | 역할 |
|---|---|
| `skills/harnessay/harnessay.py` | Claude/Codex 파싱 → 공통 이벤트 → 집계 → HTML |
| `skills/harnessay/evalrun.py` | Claude 또는 Codex CLI 실행, 출력 검사, 결과 누적 |
| `skills/harnessay/test_harnessay.py` | 합성 기록으로 파서·집계·후보 규칙 검증 |
| `skills/harnessay/test_evalrun.py` | 실제 모델 호출 없이 실행 성공·실패·입력 검증 |
| `skills/harnessay/SKILL.md` | 두 호스트가 함께 사용하는 실행 지침 |
| `skills/harnessay/eval/tasks*.json` | 호스트별 회귀 과제 예시 |
| `.agents/skills/harnessay` | Codex가 공용 스킬을 발견하는 상대 심볼릭 링크 |
| `.claude-plugin/` | 기존 Claude 플러그인 배포 메타데이터 |
| `AGENTS.md` | Codex 등 코딩 에이전트의 개발·검증 지침 |
| `README.md`, `README.ko.md` | 설치·사용법·지원 범위 |
| `docs/report-example.png` | 기존 Claude 리포트 예시 이미지 |

## 2. 이번에 적용한 내용

### Codex 지원

- `--source claude|codex|all`을 추가했습니다. CLI 기본값은 `all`입니다.
- Codex의 날짜별 하위 폴더에서 rollout JSONL을 찾습니다. 기본 경로는
  `$CODEX_HOME/sessions` 또는 `~/.codex/sessions`이며 `--codex-dir`로 바꿉니다.
- 작업 디렉터리, 일반·커스텀 도구 호출과 결과, 토큰 사용량, 압축 기록을
  기존 통계에 연결했습니다. 중복되는 사용량 이벤트는 합산하지 않습니다.
- 구버전 누적 사용량과 신버전 응답별 사용량을 지원합니다. 구버전 세션을
  신버전에서 재개해도 이전 사용량을 보존합니다.
- Codex 프로젝트에는 `codex:` 접두사를 붙이고 하위 에이전트 출력은 별도 집계합니다.
- 이 저장소에서 `$harnessay`로 쓸 수 있도록 `.agents/skills`에 연결했습니다.
  사용자 전체 설치는 변경하지 않았고, README에 설치 명령을 안내했습니다.
- 회귀 실행기에 `--provider codex` 및 태스크별 `provider`를 추가했습니다.
  Codex는 읽기 전용 환경에서 실행하며 마지막 답변 파일로 판정합니다.
- 기존 `aggregate(path)` 호출과 기본 Claude 회귀 실행 방식은 유지했습니다.

### 함께 수정한 정확도 문제

| 기존 문제 | 적용한 수정 |
|---|---|
| 한글 문자 수를 바이트로 표시 | UTF-8 바이트 수로 계산 |
| 병렬 Read 결과를 도착 순서로 파일에 연결 | 호출 ID로 정확히 연결 |
| 압축 후 필요한 재읽기도 낭비로 계산 | 압축 경계에서 판정 상태 초기화 |
| 실패한 Read의 오류 문구가 재읽기로 잡힐 수 있음 | 실패 결과를 재읽기 판정에서 제외 |
| 날짜 이전 호출의 이후 결과가 `?`로 분류 | 연결 정보는 보존하고 집계 이벤트만 필터링 |
| 기간에 해당하지 않는 세션도 개수에 포함 | 선택된 이벤트가 없는 세션 제외 |
| 같은 Claude 메시지의 사용량을 여러 번 합산 | 메시지 ID별 최종 사용량으로 집계 |
| Claude의 중첩 하위 에이전트 로그 누락 | 하위 디렉터리 로그 포함 |
| CLI가 실패해도 출력에 정답이 있으면 PASS | 종료코드·오류 응답·시간 초과·실행 오류 확인 |
| 잘못된 평가 파일을 실행 도중 발견 | 전체 태스크 형식·검사식 사전 검증 |
| 평가 결과에 실행 호스트 정보가 없음 | provider와 지정 모델 기록 |

## 3. 다음에 수정하면 좋은 부분

| 우선순위 | 개선 | 이유와 최소 구현 방향 |
|---|---|---|
| 높음 | 포크·재개·하위 에이전트의 이력 중복 처리 | Codex 포크에 복사된 과거 이벤트를 새 작업으로 셀 수 있습니다. 원본 세션·응답 ID를 보존하고 실제 새 이벤트와 구분해야 합니다. |
| 높음 | 파서의 입력 상태 진단 | JSON 문법 오류와 객체가 아닌 행은 건너뛰지만, 중첩 필드 타입까지 검증하지 않습니다. 읽은 파일·건너뛴 행·미지원 이벤트 수를 표시하고 손상된 한 행이 전체 분석을 막지 않게 해야 합니다. |
| 높음 | 회귀 검증의 의미 강화 | 문자열을 말한 것만으로 스킬 수행을 증명하지 못합니다. 생성 파일 존재·리포트 핵심 내용·허용된 테스트 종료코드 검사를 추가하면 신뢰도가 올라갑니다. |
| 중간 | Codex `exec` 내부 호출 구분 | 현재는 외부 래퍼 하나로 보입니다. 로그의 구조화된 메타데이터가 제공하는 범위에서 하위 도구를 구분하고, 임의 코드 실행이나 추측성 셸 파싱은 피하는 편이 좋습니다. |
| 중간 | 서로 다른 세션 기준의 자주 읽는 파일 | 현재 5회 기준은 호출 수입니다. 세션 수를 함께 집계해야 지침 파일로 옮길 후보를 더 정확히 고릅니다. |
| 중간 | 스킬 후보의 근거·명령 구분 | `git status`와 `git commit`이 모두 첫 단어 `git`로 묶입니다. 안전하게 구분 가능한 명령과 예시 세션을 보여주면 실용성이 높아집니다. |
| 중간 | 같은 프로젝트의 호스트 통합 | Claude 디렉터리명과 Codex cwd가 별도 프로젝트로 보입니다. 프로젝트 경로 메타데이터를 기준으로 연결하되 근거 없는 문자열 역변환은 피해야 합니다. |
| 중간 | 평가 실패 이력의 설명력 | 현재 영구 결과에는 성공 여부·시간·provider·지정 모델만 남습니다. 실패 종류와 짧은 오류 요약, 검사 설정의 식별값이 있으면 회귀 원인을 비교하기 쉽습니다. |
| 낮음 | CLI 경로·출력 오류 안내 | 잘못된 Claude 경로와 실제 기록 없음, 출력 디렉터리 없음 등을 구분해 짧고 구체적으로 안내하면 좋습니다. |
| 낮음 | 최소 CI·배포 안내 | 두 오프라인 검사를 CI에 추가하고 Python 지원 버전 및 Windows의 심볼릭 링크 설치 대안을 검증하면 배포 안정성이 올라갑니다. |

이 표에서 “가능성”으로 설명한 항목은 아직 모든 실제 이력에서 재현·측정한
결함이라는 뜻이 아닙니다. 적용 여부는 상단의 후속 적용 현황을 참고하세요.

## 4. 추가하면 좋은 기능

| 순서 | 기능 | 사용자가 얻는 결과 |
|---|---|---|
| 1 | 변경 전후 비교 | `--until`, JSON 내보내기, 같은 길이의 두 기간 비교로 지침·스킬 변경의 효과 확인 |
| 2 | 세션 원문 추적 | 큰 출력·재읽기·스킬 후보에서 관련 기록 파일과 행 위치로 이동 |
| 3 | 프로젝트·기간 필터 | 특정 저장소와 날짜 범위만 빠르게 분석하고 호스트별 결과 비교 |
| 4 | 낭비 유형별 실행 제안 | 긴 테스트 출력, 반복 탐색, 잦은 압축에 대해 근거를 붙인 개선 제안 |
| 5 | 스킬 후보 평가 보강 | 단순 횟수에 고유 세션 수·관련 프로젝트·예시 흐름을 함께 표시 |
| 6 | 검토용 스킬 초안 내보내기 | 선택한 후보만 SKILL.md 또는 AGENTS.md 초안으로 저장하고 사용자가 검토 |
| 7 | 선택적 경로 익명화 | 공유용 리포트에서 홈 디렉터리와 프로젝트 이름을 가리기 |
| 8 | 큰 이력의 증분 분석 | 실제 실행 시간이 길어질 때 파일 변경 정보 기반으로 재분석 범위 축소 |

가장 먼저 **측정 신뢰도 → 변경 전후 비교 → 원문 추적** 순서로 진행하는 것이
좋습니다. 자동 스킬 설치·서버·DB·별도 웹 프레임워크·실시간 감시는 현재 단계에서
추가할 필요가 적습니다. 정밀 토크나이저도 실제 비용 비교가 필요해질 때 검토하면 됩니다.

## 5. 검증과 현재 한계

- 2026-09-28 동일 모델로 실제 A/B 20회와 환경 보정 4회를 실행했습니다.
  일부 과제는 빨라졌지만 일괄적인 절감 효과는 확인하지 못했습니다.
  환경 실패와 재채점 내역을 포함한 [실험 보고서](BENCHMARK.ko.md)를 참고하세요.
- 기존 검사 및 추가한 합성 입력 검사를 통과했습니다.
- Claude/Codex CLI의 성공·실패·오류 응답·시간 초과·미설치 상황을 모의 실행으로 검사했습니다.
- 실제 로컬 기록으로 `report-codex.html`과 `report-all.html`을 생성했습니다.
  이 파일은 개인 데이터가 포함될 수 있어 Git에서 제외합니다.
- 2026-09-28 실제 Codex 모델 호출도 실행했습니다. 기본 모델 설정으로
  `codex-sanity-echo`가 6.6초에 PASS(1/1)했고, 정확한 `PONG` 응답을 확인했습니다.
  이는 CLI 연결·응답 검증이며 실제 harnessay 스킬 실행이나 리포트 생성 검증은 아닙니다.
  실행 결과는 `skills/harnessay/eval/results.jsonl`에 기록했습니다.
- Codex 셸 읽기를 Claude `Read`처럼 해석하지 않으므로 파일별 재읽기 통계는
  아직 Claude의 구조화된 Read만 대상으로 합니다.
- 기본 입력은 활성 로컬 세션입니다. 보관된 기록과 클라우드 전용 대화는 자동 수집하지 않습니다.
- 토큰 추정은 UTF-8 bytes/4이며 과금 수치가 아닙니다. 이미지 등 비텍스트 크기는 제외합니다.
- 공식 스킬 연결 방식: https://developers.openai.com/codex/skills
