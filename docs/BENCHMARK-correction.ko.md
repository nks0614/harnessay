# harnessay 실제 모델 비교 실험

이 문서는 원래 20회 실험에서 임시 파일 쓰기가 막힌 검사 과제를 별도 환경에서 재실행한 결과입니다.
첫 실행은 출력 없이 정상 종료한 검사를 채점기가 잘못 실패 처리했습니다.
원본 기록을 보존하고 실제 명령·종료코드 기준으로 네 실행 모두 재채점한 결과를 아래 집계했습니다.
[전체 실험과 한계](BENCHMARK.ko.md)를 함께 읽어야 합니다.

모델: `gpt-6-astra` · 추론: `high` · CLI: `codex-cli 0.154.0`
실행 환경: `workspace-write` · 스냅샷: `54e06bc78c035c6b20e920ea04769f6c96451f00461903470d0cfaca5331566e`

동일 소스에서 유지보수 작업 1개를 조건별 2회씩 실행했습니다. 총 4회이며 독립된 작업 수는 1개입니다.
기존 지침을 유지한 baseline과, 제한된 탐색·출력을 권하는 짧은 안내를 추가한 guided를 비교했습니다.
추가 안내는 harnessay의 셸 출력 분석을 참고해 사람이 작성했으며 자동 생성 결과가 아닙니다.

정답 및 실행 검증: baseline **2/2**, guided **2/2**.

## 해석 범위

- 모든 실패와 시간 초과를 포함했습니다. 성공한 결과만 골라 집계하지 않았습니다.
- baseline 먼저 1쌍, guided 먼저 1쌍으로 순서를 균형 있게 무작위 배치했습니다. 캐시는 완전히 통제하지 못했습니다.
- 안내문 자체의 토큰도 guided 사용량에 포함됩니다. 시간이 줄었다고 요금이 같은 비율로 줄었다고 볼 수 없습니다.
- 무인 실행으로 실제 사용자 개입은 두 조건 모두 0회입니다. 개입 감소 효과는 검증하지 않았습니다.
- 한 저장소의 작업 1개로, 코드 수정 품질·다른 저장소·장기 사용에 일반화할 수 없습니다.
- 일반적인 효율 지침의 효과를 탐색한 실험입니다. harnessay만의 독점적 효과나 전체 제품의 절감률을 증명하지 않습니다.
- 재현 조건·정답·순서는 manifest에 고정했고, 읽은 소스의 해시와 압축 사본을 보관했습니다.
