# harnessay 실제 모델 비교 실험

**판단: 일부 작업은 개선됐지만, 일괄적인 시간·토큰 절감이나 제품의 경쟁 우위는 입증하지 못했습니다.**
실제 호출은 원래 실험 20회와 환경 보정 실험 4회, 총 24회입니다.
원래 검사 과제의 환경 실패 4회는 아래에 보존했고, 보정 결과는 별도 집계했습니다.

모델: `gpt-6-astra` · 추론: `high` · CLI: `codex-cli 0.154.0`
실행 환경: `read-only` · 스냅샷: `54e06bc78c035c6b20e920ea04769f6c96451f00461903470d0cfaca5331566e`

동일 소스에서 유지보수 작업 5개를 조건별 2회씩 실행했습니다. 총 20회이며 독립된 작업 수는 5개입니다.
기존 지침을 유지한 baseline과, 제한된 탐색·출력을 권하는 짧은 안내를 추가한 guided를 비교했습니다.
추가 안내는 harnessay의 셸 출력 분석을 참고해 사람이 작성했으며 자동 생성 결과가 아닙니다.

## 해석 범위

- 모든 실패와 시간 초과를 포함했습니다. 성공한 결과만 골라 집계하지 않았습니다.
- baseline 먼저 5쌍, guided 먼저 5쌍으로 순서를 균형 있게 무작위 배치했습니다. 캐시는 완전히 통제하지 못했습니다.
- 안내문 자체의 토큰도 guided 사용량에 포함됩니다. 시간이 줄었다고 요금이 같은 비율로 줄었다고 볼 수 없습니다.
- 무인 실행으로 실제 사용자 개입은 두 조건 모두 0회입니다. 개입 감소 효과는 검증하지 않았습니다.
- 한 저장소의 작업 5개로, 코드 수정 품질·다른 저장소·장기 사용에 일반화할 수 없습니다.
- 일반적인 효율 지침의 효과를 탐색한 실험입니다. harnessay만의 독점적 효과나 전체 제품의 절감률을 증명하지 않습니다.
- 재현 조건·정답·순서는 manifest에 고정했고, 읽은 소스의 해시와 압축 사본을 보관했습니다.

## 최종 과제 판정을 기준으로 구분한 해석

원래 20회에서 실패한 4회는 모두 오프라인 검사 과제였습니다. 읽기 전용 샌드박스가
검사에 필요한 임시 파일 생성을 막았고, 모델은 실패를 그대로 보고했습니다.
이는 모델의 사실 판단 오류가 아닙니다. 위 전체 집계에는 해당 4회를 그대로 보존했습니다.

나머지 **4개 과제·16회는 최종 정답 검증에서 양쪽 모두 8/8 통과**했습니다.
다만 이 실행들까지 환경 문제에서 자유로웠다는 뜻은 아닙니다. 후속 원시 기록 조사에서
날짜 확인 등에서도 임시 파일 오류 후 추가 검증을 수행한 것을 확인했습니다.
아래는 최종 과제 판정으로 구분한 부분집합이며, 환경을 통제한 비교나 원래 실험의 대체물이 아닙니다.

포크 확인은 두 반복 모두 빨라졌지만, 날짜 확인은 두 반복 모두 느려졌습니다.
셸 출력 감소가 곧 모델 처리량·완료 시간 감소로 이어지지는 않았습니다.
지침 자체의 효과와 환경 오류 후 복구 행동의 영향을 현재 기록만으로 분리할 수 없습니다.

## 제품에 대한 판단

이 결과만으로 “자동으로 토큰을 절약하는 제품”이라고 주장하기는 어렵습니다.
측정·원문 추적·변경 전후 비교는 유용하지만, 이번 안내문은 사람이 작성한 일반 지침입니다.
harnessay 자체의 고유 효과나 다른 도구 대비 우위는 측정하지 않았습니다.

다음 개발 우선순위는 기능 수를 늘리는 것보다, **개선 제안마다 같은 과제를 재검증하고
악화된 제안도 표시하는 것**입니다. 이번 파일럿은 그 검증 절차와 실패 기록을 남겼습니다.
다른 저장소와 실제 코드 수정 과제로 효과가 반복되는지 확인한 뒤 절감 주장을 해야 합니다.

## 오프라인 검사 환경 보정: 별도 4회

동일 모델·지침·소스 해시를 유지하고, 임시 스냅샷 쓰기를 허용하는
`workspace-write`에서 검사 과제만 각 조건 2회씩 실행했습니다.
소스 파일이 변경되지 않았고, 모든 실행에서 세 검사 명령의 종료코드가 0임을 확인했습니다.
baseline **2/2**, guided **2/2** 통과입니다.

첫 보정 실행은 검사 하나가 출력 없이 정상 종료하여, 성공 문구를 요구하던 채점기가
잘못 실패로 표시했습니다. 실제 Python 명령·종료코드를 검사하도록 채점기를 수정하고
회귀 검사를 추가했습니다. 원시 `results.jsonl`은 보존했고, 4회 모두 같은 수정 기준으로
재검사한 `reviewed-results.jsonl`을 별도 저장했습니다. 원래 20회의 판정은 바뀌지 않았습니다.

이 보정 실험에서도 두 조건의 품질은 같고 일관된 시간 절감은 확인되지 않았습니다.
원래 실험의 실패를 성공으로 교체하거나 환경이 다른 기록을 한 집계에 섞지 않았습니다.
호출별 수치와 원시 기록 위치는 [보정 실험 상세](BENCHMARK-correction.ko.md)에 있습니다.
